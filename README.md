# MSBA Designer Selection Intelligence

Research platform for public Designer Selection Panel (DSP) results from the Massachusetts School Building Authority. It estimates which observable firm histories are associated with being ranked first among published finalists, checks those estimates against simple baselines, and keeps design quality, cost efficiency, and selection success as separate ideas.

The platform does not assume favoritism or misconduct. A low predicted probability is an unexpected model outcome, not a finding about the panel.

## What is estimated

The question that this archive can answer is: **given the firms the DSP published as finalists or as a ranked set, which firm was placed first?**

It does not estimate the probability of being shortlisted from the full applicant pool. Historical pages usually omit firms that were not advanced. Individual panelist votes are not published and are not invented. Architectural design quality is not directly measured. The linked designer construction cost chart is not in this snapshot, so cost performance is not scored. Schematic-design costs would also be known only after selection.

## Sources

Official pages and the local snapshots are listed in `src/msba_dsp/ingestion/sources.py` and hashed into `data/manifests/sources.csv` when the pipeline runs.

Included snapshots:

- DSP result pages for 2007–2009, 2010–2014, 2015–2018, and 2019–2024.
- The 2025–2026 DSP meeting result chart (applicants, shortlists, ranks, and preselection cost ranges).
- The January 2026 procedures PDF and the public process page, used to describe the stated criteria. They are not result tables.

Not included, and therefore not used in a model:

- Designer construction cost chart (PDF and Tableau).
- Capital-planning project and cost portals.
- Firm websites, headquarters, or marketing claims.

## Run

```powershell
python -m pip install -e ".[dev]"
python run_pipeline.py
python -m pytest
```

`MSBA_BOOTSTRAP` controls the number of competition-resampled draws (default 40). `MSBA_SEED` defaults to `20261020`.

The pipeline rereads the local HTML and Excel snapshots, writes processed tables and `data/processed/msba_dsp.sqlite`, writes `reports/`, and refreshes `dashboard/platform.js`.

Open the dashboard with a local server so the browser can load the scripts:

```powershell
python -m http.server 8765 --directory dashboard
```

Then open `http://127.0.0.1:8765/`.

## How the sample is built

A competition enters the winner model only when the publication lists at least two firms and exactly one top-ranked firm. Repair pools, informational interviews, and unranked shortlists are stored and are not treated as wins.

When a page says a list is a ranking but prints bullets instead of numerals, rank follows the published order and the row is flagged `published_list_order`.

Firm names lose only case, accents, punctuation, and legal suffixes automatically. Further matches are an explicit reviewed list in `src/msba_dsp/processing/names.py`. Joint ventures and “in association with” lines keep their own identifiers. The alias audit is `data/processed/firm_alias_audit.csv`.

Experience variables use earlier calendar dates only. Two selections on the same day do not update each other. A firm with no earlier row is an archive newcomer, not necessarily a new practice. The archive starts in 2007.

## Models

| Model | Role |
| --- | --- |
| Equal probability, prior wins, grade wins, shrunk win rate | Baselines |
| Conditional logit | Primary interpretable model. Probabilities sum to one inside each choice set. |
| Penalized firm effects | Partial pooling. A residual after experience covariates, not a quality score. |
| Choice-set-normalized gradient boosting | Nonlinear check. Importance is not causal. |
| Plackett-Luce rating | Historical selection strength when firms meet. Walk-forward ratings use only earlier years. |

Out-of-sample scores for 2019 onward are fit on competitions through 2018. The project does not use a random split across time. Top-choice accuracy requires a unique favorite, so an equal-probability baseline scores zero on that metric. Log loss is the measure that compares it with the other models.

Project-level facts such as year or grade do not, by themselves, choose a winner. They enter only through interactions with a firm attribute.

## Reports

- `reports/source_inventory.md` — what each source can and cannot support.
- `reports/data_quality.md` — counts, rank rules, and exclusions.
- `reports/research_report.md` — metrics, coefficients, and hypothesis results. Generated by the pipeline, not written in advance.

## Layout

```text
data/raw/            public snapshots
data/reference/      DSP procedures and landing page
data/processed/      research tables and SQLite
data/manifests/      source hashes
src/msba_dsp/        ingestion, resolution, models, reports
dashboard/           research terminal
reports/             generated notes
tests/               name resolution, leakage, and choice probabilities
```

## Updating

Add a new MSBA result snapshot under `data/raw`, point `src/msba_dsp/ingestion/sources.py` at it, and rerun `python run_pipeline.py`. Keep the previous file if you replace a page, and let the manifest record the new hash. Do not fill missing votes, costs, or firm attributes by hand inside the model tables.
